# tokenizer

Byte-level BPE.

`Tokenizer::train` learns a merge list from text. `RankTokenizer::load_cl100k` loads OpenAI's cl100k vocab (`bytes -> rank`). `RankTokenizer::encode` splits on special tokens, then on the cl100k regex, then byte-pair-encodes each piece. The vocab file is not in git.

## Tests

`cargo test` runs the proptest suite (`prop_round_trip_bytes`, `prop_matches_tiktoken_rs`) at 10,000 cases. Those tests download the cl100k vocab on first use. `PROPTEST_CASES` overrides the count (for example `PROPTEST_CASES=256 cargo test prop_`). The other tests do not need the vocab file or `book.txt`.

The cl100k file is cached at `~/.cache/tokenizer/cl100k_base.tiktoken`. Download it with:

```bash
scripts/fetch-cl100k.sh
```

`cargo test --release -- --ignored` downloads that file with `curl` when it is missing, checks the sha256 published with tiktoken, and also runs `fast_training_matches_naive_on_book`, which needs `book.txt` in the repo root (gitignored).

The pairs in `encode_piece_matches_known_ids` come from `scripts/gen_cl100k_pieces.py` (tiktoken 0.14.0, `Encoding._encode_single_piece`). That is piece encoding, with no regex split.

`tests/fixtures/cl100k_cases.jsonl` is full-text encode, generated by `scripts/gen_cl100k_cases.py` (same tiktoken). `encode_matches_tiktoken_fixtures` and `encode_matches_tiktoken_on_book` are ignored with the other cl100k tests. The book one also needs `book.txt` and `python3` with tiktoken. `cargo bench --bench cl100k_encode` reports encode throughput on that book.
